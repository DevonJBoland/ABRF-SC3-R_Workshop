3.1.1 Hello, world!

In all seriousness though, coding can be as simple or complex as you make it. For instance, we are going to begin by writing the first program everyone learns in any programming language, printing the Hello, world! statement. We will use the print() function from base R. We will go over each part of it shortly. Begin, typing the following in your R script:

print("Hello, world!")
[1] "Hello, world!"

As you can see the statement “Hello, world!” was output (or printed, hence the function name) below in our R console. We called the print() function which takes as input a string (text), number, or even a variable as input. This print() function is used a lot across many programming languages. You have commonly encountered it in your day-to-day jobs. When coding it is often used to print a status update, error message, warning, etc. to the user as feedback so we aren’t just starting at a static screen wondering if something has happened or we have messed up.

Now we are going to add a layer to our print() code from earlier. What if we wanted to store a message to ourselves, say remember to drink our coffee while it is still hot, and view it later. We achieve this by creating a variable and casting (storing) a value in it using the <- operator.

3.1.2 Vector, the simplest way to store multiple data

Above we stored our first data, a single string into the variable note. But what if we wanted to store a list of numbers? In R, a series of data is called a vector (in R we also have list objects, which behave differently but can look similar). We begin a vector using the c() and separating elements in the vector with a comma. Below, let’s create a vector of numbers 1-5.

num_vec <- c(1,2,3,4,5)
print(num_vec)
[1] 1 2 3 4 5

As you can see, we stored a list of the numbers 1-5 in the variable called num_vec. Unlike before, our variable now stored as numbers, specifically as integers. You’ll notice how we dropped the "" marks as we intended to store numbers instead of strings.

However we can mix data types in vectors, lets see what happens when we try to mix numbers and strings:

mix_vec <- c(1, "the", 2, "cow", 3, "moos")
print(mix_vec)
[1] "1"    "the"  "2"    "cow"  "3"    "moos"

3.1.3 Comments

And to help us understand our code later, we add “comments” which start with a hashtag #. When our script runs, comments don’t actually do anything. However, they help document our code so that later on we know what we are reviewing our code, we can see what were thinking when we wrote it.

# Comments can be an entire line, or come at the end of code

# Create a mixed type vector (for a demo)
mix_vec <- c(1, "the", 2, "cow", 3, "moos") # commas separate values

print(mix_vec)
[1] "1"    "the"  "2"    "cow"  "3"    "moos"

3.1.4.1 Accessing Data inside Dataframes/Tibbles

Now let’s take a look on how to access rows, columns, and specific values using base R’s indexing methods. First let’s see how we can view the row and column names of a dataframe:

1print(rownames(combined_df))
2print(colnames(combined_df))
1
rownames() returns a vector of the row index names, or numbers if no names are present
2
colnames() returns a vector of the column names, or numbers if no names are present. 
[1] "1" "2" "3" "4"
[1] "name"  "value"

Above we can see that, the row indexes are numbers, and our column names are “name” and “value”. We can use the rownames() and colnames() functions to replace the old labels with new ones if we wanted to as well. Next lets see how we print specific rows:

print(combined_df[1,])
  name value
1    A     5
print(combined_df[3,])
  name value
3    C    15

Here the numbers represent coordinates where the x-value corresponds to row number, and the y-value corresponds to a column number within the dataframe. By leaving the second value empty (after the comma) we print a single row. The same would be true if we switched the numbers around, and we would print a column instead. To access specific data, we use both coordinate values:

print(combined_df[1,2])
[1] 5

3.1.5 Pipes

Functions in R and many other programming languages are evaluated “inside first”.

This can get to look really messy sometimes, like this:

print(sqrt(sum(sqrt(100),26)))

What is even going on here?

It’s basically the following:

print(sqrt(sum(sqrt(100),26))) # sqrt(100)  gets replaced by 10
print(sqrt(sum(10,26)))        # sum(10,26) gets replaced by 36
print(sqrt(36))                # sqrt(36)   gets replaced by 6
print(6)                       # Prints the answer: 6

So, the first function that we see, reading left-to-right, is actually the last one that runs.

This is where pipes can be helpful. They take their input from the left and put it in as the first argument in the function on their right. Here’s the same code written with the native pipe |>:

sqrt(100) |> sum(26) |> sqrt() |> print()

Or, with each step on its own line:

sqrt(100) |>
 sum(26)  |>
 sqrt()   |>
 print()

Now, reading left-to-right or top-to-bottom, we see things happen in the same order that they are written.

  • take the square root of 100
  • add that result to 26
  • take the square root of that answer
  • and then print it.

Same thing, but with in-line comments:

sqrt(100) |>            # take the square root of 100           # 10
 sum(26)  |>            # add that result to 26                 # 36
 sqrt()   |>            # take the square root of that answer   #  6
 print()                # print the final result
